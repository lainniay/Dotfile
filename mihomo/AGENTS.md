# Mihomo 配置维护约定

## 文件职责

- `base.yaml`：管理 Mihomo 核心配置，包括代理监听端口、DNS、连接行为、日志及 profile 等；不在此维护分流规则或策略组。
- `mctl.json`：管理分流规则、策略组（group）的定义及节点筛选规则，包括 `rules`、`groups`、`default_group` 等。
- 最终运行配置由 `base.yaml` 与 `mctl.json` 渲染产物组合生成。修改源文件，不直接修改生成文件；修改后需重新渲染并重载才能生效。

## 当前运行方式

- 不使用 Mihomo TUN；应用通过 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 等环境变量使用本机代理。
- 主要节点为自建 VPS 上的 Shadowsocks 2022（SS2022），通过 `Pro` 策略组选择。
- GPT 相关域名统一使用 `Pro`，包括 `chatgpt.com`、`openai.com`、`oaistatic.com`、`oaiusercontent.com` 及其子域名。注意前置精确匹配规则不得将登录等请求分流至其他出口。
- 默认 DNS 使用经 `Pro` 的 DoH；节点域名通过独立直连 DoH 解析，避免循环依赖；直连目标使用国内 DoH。`ts.net` 保留系统解析策略，不能假定系统 MagicDNS 已正确配置。
- Mihomo 内置 DNS 不等于接管系统 DNS。对于 curl 等支持该约定的应用，使用 `socks5h://` 可将域名交给代理解析；不要将 `socks5://` 误认为远端解析。

## 调优优先级

1. **首先保证 `chatgpt.com` 连接稳定性**：登录、长时间流式生成、闲置后恢复、上传和下载均应可靠。
2. **其次降低不必要的识别与风控风险**：避免 DNS 泄漏、异常出口切换和相关请求出口不一致；坚持正常、合规使用，不承诺不可识别或绕过平台限制。
3. **最后优化速率与延迟**：不能为了测速成绩牺牲连接可靠性或出口一致性。

## 调优策略

### 稳定出口与 DNS

- 日常将 `Pro` 固定到已验证可用的自建 VPS，避免频繁自动切换、轮换 IP 或将 GPT 请求分散到多个出口。
- GPT 登录、API、静态资源及附件域名保持同一策略组；新增相关域名时检查规则顺序，避免被前置规则覆盖。
- 默认 DNS 与 GPT 连接均经 `Pro`，避免依赖另一个代理组的可用性。DNS 经代理不保证目标站点一定由本地解析，需结合实际连接链路判断。
- 优先使用校验证书的加密 DNS，不为可用性关闭 TLS 证书验证，不随意加入明文 DNS 回退。
- 前置私网 `IP-CIDR` 规则优先考虑 `no-resolve`，减少域名规则之前的额外解析；变更前确认是否依赖域名解析结果进行私网分流。
- 保留 Tailscale 和内网访问能力，不将内网域名无差别交给公共 DNS。

### 连接参数与速率

- 保留现有 `tcp-concurrent` 等合理设置，但不要将 `unified-delay` 当作实际流量加速。
- 无明确需求不启用 TUN、fake-ip、嗅探、强制 HTTP/3 或额外复用；不盲目调整 MTU、TCP 参数或协议。
- 只有出现闲置后断连且有排查依据时，才考虑调整 TCP keepalive。保活不等于应用层心跳，不能防止服务端主动断开，也不直接提高吞吐。
- SS2022 无需套用所谓通用加速模板。优先排查本地到 VPS 的丢包与拥塞、VPS 资源和带宽、服务端日志、VPS 到 OpenAI 的连通性。
- 不默认调整 VPS 系统参数；涉及服务端、协议或基础设施变更时，先说明收益、风险与回滚方式并获得确认。

### “不容易被识别”的边界

- 区分网络侧协议识别与网站侧 IP 信誉、反滥用风控，两者不能靠同一组 Mihomo 参数解决。
- SS2022 提供加密，但不等于 HTTPS 伪装，也不保证无法被流量分析识别；DoH 也不隐藏全部网络元数据。
- 自建 VPS 不代表住宅 IP 或可信 IP，无法保证不触发 Cloudflare 验证或 OpenAI 限制。
- 优先采用稳定出口、正常请求行为、减少泄漏和标准安全配置；不以规避平台封禁、验证码或反滥用机制为调优目标。
- 不盲目叠加混淆或伪装方案。若确有网络侧干扰证据，先诊断，再评估兼容性和性能代价；不得声称任何方案“不可识别”。

## 修改与验证

- 先读取当前源文件，只修改与任务相关的内容，不泄露节点密钥、订阅地址或其他凭据。
- 修改 Mihomo 配置字段前查询当前版本文档，并检查本机版本支持情况。
- 修改 `mctl.json` 后验证 JSON 语法、策略组引用、规则顺序及 GPT 域名出口一致性。
- 修改 `base.yaml` 后优先对最终渲染配置执行 `mihomo -t`。若仅能用临时策略组验证，明确这只是配置校验，不代表真实节点链路已通过测试。
- 运行测试应尽量无侵入，不擅自重启服务或修改系统 DNS。配置校验、实际代理测试和系统 DNS 测试分别报告。
- DNS 结果不同不直接等于污染，应结合地址合理性及通过代理访问的多个可信 DoH 结果交叉验证。
- 每次调优尽量只改变一个因素，以连接成功率、流式连接中断情况、闲置恢复和实际吞吐判断收益；保留可回滚路径。
